# Rev.A — HID仕様と入力変換

## 入力方式

- USBデバイス: HID **1インターフェース / 2トップレベル・アプリケーションコレクション**方式（Report ID 1 = Keyboard; 2 = Gamepad）。「キーボード + ゲームパッドの複合HID」に相当する。
- Gamepad report: `[ID=2][buttons(3bit+padding)][X axis(int8)]`、送信長3 byte。Xは絶対軸、論理最小値-127、最大値+127、中立0。
- 回転はGray-code遷移4回を1単位として数え、CWで正、CCWで負。左右が逆の個体は `ENCODER_REVERSE` で入れ替える。
- 回転速度（直前のステップ間隔）に応じて絶対値32〜127で出力。初回ステップは64。10ms以下127、110ms以上32、間は線形補間。
- 最終有効ステップから120ms経過した時点で軸を0へ自動復帰（機械的な中央位置は不要）。USB転送失敗時はゲームパッドの最終状態を再試行する。
- F1/F2/PTTは各々 `KEYMAP_*` と `*_AS_GAMEPAD_BUTTON` で**コンパイル時**に任意指定。初期はキーボード '1','2','p'。ゲームパッドButton1-3として出す選択も可能。同一接点の二重送信は行わない。
- F1/F2/PTTは押下→HID Press、解放→HID Release。PTTはトグルしない。

## 注意点と限界

1. 標準ジョイスティック軸は絶対値です。エンコーダーの無限回転位置の絶対角度を意味しません。**回転を速度指令に置き換えた実装**です。周波数調整量はWebTRX側のポーリング頻度と感度設定に依存します。
2. WebTRXのブラウザ側にGamepad APIを読み取る処理がなければ、USBゲームパッドとして認識されてもWebTRXを操作できません。Gamepad API接続/権限/フォーカス挙動は要確認。
3. USBキーボード機能は、現在フォーカスしているウィンドウに入力を送ります。WebTRXの正式なショートカットは未確認。
4. PTTをWebTRXへ割り当てる前に、アプリ側にUSB切断・入力途絶・ウィンドウ非アクティブ・操作権喪失時の送信停止とタイムアウトを実装/検証する必要があります。OSのキーアップ受信だけに安全を依存しません。
5. CH552Tは内蔵RAMとUSBバッファが小さいため、`src`にある上流のUSBサンプルへ最小パッチを適用する構成です。USB列挙、Windows Game Controllers、全押下/解放動作、Arduino 0.0.26のビルドは未検証。

## HIDレポートの例

- `02 00 40` … ボタンなし、X=+64（正転）
- `02 00 C0` … ボタンなし、X=-64（反転）
- `02 00 00` … 停止/中立
- `02 01 00` … Button1押下（Button出力設定時）
- Keyboardは `01` の後ろに8byteの標準6キー報告。

## テスト観点

Windows `joy.cpl`: ゲームパッドX軸の中立・正転・反転とButtonを確認。テキストエディターではキーボードHIDとPTTの連続押下を確認。`USBView`でVID/PID、製品名、Report Descriptor、Report IDの構造を確認。

現時点ではこれらを**実施済みと表記しない**。
