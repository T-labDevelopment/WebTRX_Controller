# Rev.A — HID仕様（24クリック・1カウント方式）

## 採用部品・入力

- エンコーダー: ALPS Alpine **EC12E2420801**、秋月電子106357、24クリック/24パルス、A/B 2相。1回転=24クリック=24カウント。
- MCU: WeAct CH552 Core Board V1.0 (CH552T)。配線はP1.4(A)、P1.5(B)、GND(C)。F1=P1.6、F2=P1.7、PTT=P3.2。
- 4相(Gray)遷移を合計4回検出して**1クリック**。A/B入替や個体の回転方向の差は `ENCODER_REVERSE` で反転。ボタン設定は従来どおり。

## USB HIDレポート

- 1つのHIDインターフェース、2つのApplication Collection：Keyboard Report ID=1、Gamepad Report ID=2。
- Gamepad report: `[02][buttons(3bit+padding)][X int8]`。X論理範囲: **-127～+127**、中立0。
- 時計回り1クリック：`02 00 7F`（+127）を送信 → **35ms以上**保持 → `02 00 00`（0）を送信 → **25ms以上**中立状態を保持。
- 反時計回り1クリック：`02 00 81`（-127） → 同様に0へ復帰。
- 時計回り2クリック： `+127 → 0 → +127 → 0`。**同符号のクリックをまとめない**。
- 回転速度に応じてX値を変化させない。累積位置、継続押下、加速度出力も行わない。
- `DIAL_ACTIVE_MS=35`、`DIAL_NEUTRAL_MS=25`、`GAMEPAD_REFRESH_MS=10` は初期値。送信成功から時間を計測し、USB忙しさによって延びる場合がある。
- 64イベントFIFOで受け取ったクリック順を保つ。キューが満杯のときは `droppedEvents` を加算して最新イベントを破棄（無制限回転での損失なしは保証不可）。毎秒最大約16.7クリックの**平均送信能力**が初期値の理論上限。高速に回し続けると遅延/溢れが発生しうる。
- F1/F2/PTT: `KEYMAP_*` (任意キーボードキー) または `*_AS_GAMEPAD_BUTTON` (Button 1～3) をコンパイル時に選択。押している間だけON、離すとOFF。入力の二重送信なし。

## WebTRXでの1カウント確定条件

標準USBジョイスティックのX軸は**絶対値**であってカウンターではない。
- WebTRX側でX=0から正の閾値を越えた時を `+1`、0から負の閾値を越えた時を `-1` として**エッジ検出**し、必ず中立復帰を確認してから次の入力を受ける。
- 初期しきい値案 `>=+100`, `<=-100`, 中立 `abs(X)<=20`。実際のゲームパッドAPI値は-1.0～+1.0へ正規化されるためソフト側のしきい値は±0.8、中立±0.15程度を初期案とする。
- ブラウザの Gamepad API はイベントキューでなく**軸の状態をポーリング**する仕組み。WebTRXの取得周期が短いパルスに追随しない場合は取りこぼす。**実機/ブラウザ上で1クリック=1カウントを保証したわけではない**。
- ダイヤルの高速カウントを完全に保証するには、デバイス側イベントキューだけでなく、WebTRX側のGamepad APIポーリング周期と応答、キュー溢れ/USB切断の対策を検証する必要がある。

## 注意点

- PTT送信安全はWebTRX側でUSB切断・入力途絶・非アクティブ時に送信停止する実装が必要。
- USB VID:PID=1209:0001は私的試験専用。製品頒布前に固有のVID/PIDを割り当てること。
- CH55xDuino **0.0.26**、USER_USB_RAMが必要。実コンパイル・USB列挙・WebTRX動作は未検証。
